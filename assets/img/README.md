# Images

Drop real photos here. The site picks them up by filename, so there's no code to change.

| File                   | Used for                  | Size        | Generated by              |
| ---------------------- | ------------------------- | ----------- | ------------------------- |
| `beth.webp`            | Hero portrait             | square ~1000px | — (a real photo)       |
| `hero-bg.*`            | Hero background photo     | 2400 × 1350 or larger | — (a real photo) |
| `og-image.jpg`         | Link preview when shared  | 1200 × 630  | `scripts/og-image.py`     |
| `apple-touch-icon.png` | iOS home-screen icon      | 180 × 180   | from `favicon.svg`        |
| `favicon.svg`          | Browser tab icon          | n/a         | — (hand-written)          |

The favicon and og-image hard-code palette values, because they are images
rather than CSS and cannot read `@theme`. **When you re-skin the site, re-run
them** — both sat in the original warm-sand palette through a whole monochrome
re-skin before anyone noticed, and the og-image is the one a stranger sees first
when the link gets pasted somewhere.

    python3 scripts/og-image.py       # needs pillow, fonttools, brotli

Keep JPEGs under about 300 KB. [squoosh.app](https://squoosh.app) is an easy way to
shrink them before committing.

## beth.webp — the portrait

The frame is a 132px circle and crops from the top, so a square headshot with
the face in the upper half sits well. Anything taller than square loses its
sides.

**It is black and white, and it stays that way.** In a hero that is otherwise
teal and cream, the one grey thing is what reads as a person rather than more
scenery. A colour headshot here competes with the water behind it.

The build reads the filename from the `src` in `index.html`, so renaming the
photo only means changing it there. If the file is missing the build drops the
`<img>` and shows a placeholder, so the page never 404s.

## hero-bg.\* — the hero photograph

Full-bleed behind the hero, under a deep teal scrim, with cream type over it. Any
of `.avif`, `.webp`, `.jpg`, `.jpeg`, `.png` works — the build takes the first it
finds in that order and points both the `<img>` and its `<link rel=preload>` at
it. Drop a file in, change nothing else. With no file at all both tags come out
and the hero is flat `--color-band` teal, which is a state the type is measured
against rather than a broken one.

This is the largest paint on the page, so **size it for a full-bleed hero**:
2400px wide at minimum for a 2× laptop display. The 1280px original the client
supplied is roughly half what a 27" screen wants.

Two things to check when the photograph changes, both because the type sits
directly on it:

- **Headline contrast.** Re-measure cream on the top-left of the crop. If it is
  short, move the *first two* stops of `.hero-scrim` in `src/input.css` — those
  are the ones under the copy. The back two only shape how much water survives on
  the right, so raising them costs brightness and buys no contrast.
- **The credential card.** It is a translucent teal panel in the right rail where
  the scrim is thinnest, so a bright patch of sky behind it eats its caption.
  `.hero-card`'s background alpha is the knob.

`object-position` is `50% 55%` — the horizon sits high in the frame and the
figure sits low, and that keeps both. It shifts to `60% 55%` under 768px, where
the sides get cropped away.
